# Bun 1.4.4 — security changelog

**Released:** 2026-10-22 10:11Z · tag `bun-v1.4.4` (`38afee6c8`)
**Previous release:** 1.4.3 (2026-10-10)
**Diff:** 172 commits · 171 PRs · 1 direct commit
**Verification:** `compare/bun-v1.4.4...main` is **identical** (0 ahead, 0 behind), so the
tag is `main`'s head and nothing in the window was left out. Every claim below was checked
in the files at the tag, not inferred from `main`.

---

## Why this document exists

The GitHub release page for 1.4.4 is **130 words**: an install snippet, a link to the blog,
and 39 contributor names. It says nothing about what was fixed. Everything below was
reconstructed from the 171 merged PRs and verified against the tag.

**Headline:** 1.4.4 closes **27 enumerated security issues** plus roughly 300 crash paths,
and closes all three published advisories that named Bun as unpatched. It is, by content
if not by label, a security release.

## CA trust — F12

**`#46300` — "tls: reject chains containing blocked public keys, update root certificates
to NSS 3.131.1"** · CVSS 8.7

* Adds `blocked_spkis.cpp`: a compiled-in list of **8** SHA-256 SPKI hashes for the
  compromised eMudhra intermediates. A chain holding one fails with `CERT_REVOKED`. Ported
  from Node's `crypto_context.cc`, uses Node's list, runs in `us_x509_verify_chain`.
* Regenerates the bundled roots from NSS **3.131.1** (118 certificates, same set as Node's,
  compared by SHA-256).
* Closes the [eMudhra intermediary CA compromise](https://emudhra.we-have-a-problem.com/).

**`#46159` — "crypto: update root certificates"** · partially superseded

* Added a `%distrusted_labels` list and removed four emSign roots (121 → 117).
* **Largely undone** by #46300 the next day; see *Known regression* below.

## Dependency CVEs — F1

**`#46392` — brotli to v1.2.1** · CVSS 8.1

* Closes **CVE-2026-111497**, an out-of-bounds write in the brotli decoder, reachable by
  default from `fetch()` on any `Content-Encoding: br` response, from `node:zlib` and from
  `DecompressionStream("brotli")`.
* Verified: `BROTLI_COMMIT = "db24a98a…" // v1.2.1` at the tag. Node shipped the same
  cherry-pick (`0ed4268a`) on 2026-10-21.

---

## HTTP/3 — F11

**`#46392` — QPACK header limits** · CVSS 7.5

* Enforces a cumulative header budget per RFC 9114 §4.2.2 (`name + value + 32` per field),
  caps a request at 200 fields, answers `431` over the limit, hard-caps buffer growth at
  `2 × max_size`.
* Closes the [FoxIO QPACK amplification attack](https://foxio.io/blog/header-accordions-qpack-amplification-attacks-against-http-3-servers)
  (~4000× wire-to-memory amplification, one connection to OOM a 2 GiB container).

**`#46436` — "lift lsquic's limits on header sizes, and honor the stream ID of a GOAWAY"**

* Follow-up: removes lsquic's internal 64 KB caps and its 16-bit `lsxpack` string lengths,
  while explicitly keeping the #46392 limits in place.
* Also fixes a GOAWAY that named the last accepted request rather than the first rejected
  one, and a replayed non-idempotent request.

## TLS — F13

**`#44618` — "consolidate the open TLS fixes"**

CVSS 7.4 on its worst item. Merged **15 hours after the 1.4.3 tag**, so every issue below
was live in 1.4.3. Reproduced on `main` and against Node v26.3.0 before changing anything.

| Fixed | Class |
|---|---|
| `WebSocket` never called `tls.checkServerIdentity`; ignored `tls.serverName` | CWE-295 |
| `NODE_TLS_REJECT_UNAUTHORIZED=0` disabled a **server's** client-certificate enforcement | CWE-295 |
| `tls: [...]` passed to `Bun.listen` / `Bun.connect` was **plain TCP** | CWE-319 |
| `https.createServer()` without a usable key/cert answered **plain HTTP** | CWE-319 |
| `secureConnect` reported `authorized === true` for a peer that failed the key proof | CWE-287 |
| `PGSSLMODE=verify-*` dropped next to a `TLS_*` URL variable | CWE-295 |
| Client certificate disclosed to a server that is then refused | CWE-200 |
| Revoked client certificates accepted — an mTLS server never saw the `crl` | CWE-299 |
| Different client certs/CAs shared one `https.Agent` socket and session | CWE-488 |
| TLS `write()` silently lost 16 KB while another socket was stalled | CWE-703 |
| Use-after-free from `destroy()` inside `ALPNCallback` | CWE-416 |
| SIGABRT in `fetch` through an environment proxy with a `Bun.file()` body | CWE-248 |
| Quadratic Duplex / CONNECT-tunnel path (32 MB: 11.75 s → 0.39 s) | CWE-407 |

**`#46335` — "tls: keep a stream TLS engine's context alive"** · CVSS 6.5

* ASAN-confirmed heap-use-after-free in `us_ssl_wrapper_keylog` / `SSLWrapper::flush_pending_events`;
  release builds ended in `panic: RefCell already borrowed`. Found by audit.

**`#43089`, `#45713`, `#45471`, `#46099`, `#46296`, `#46302`, `#46237`** — supporting
`node:tls` / `node:quic` fixes: verifying against the default CA store, IP SANs, SNI
handling, `setDefaultCACertificates` honoured by `fetch` and `WebSocket`.

## SQL — F14

**`#45304` — "consolidate the open Bun.sql, bun:sqlite and node:sqlite PRs"**

**CVSS 7.4**

* `tls.checkServerIdentity` **was never called**. The Postgres client validated the chain
  but never checked the certificate was issued for the host it connected to — any valid
  certificate from any CA passed. Now called, and it raises any `sslmode` below `verify-ca`
  to `verify-full`.
* Adds SCRAM-SHA-256-PLUS with `channelBinding: disable|prefer|require`, binding
  authentication to the TLS channel.
* `$PASSWORD` is no longer read as the database password.
* 197 open PRs folded in; 149 replaced by it.

---

## WebSocket — F15

**`#45223` — "real closing handshake, one failure path"**

**CVSS 5.3**

* A **masked** frame from a server was parsed with the mask key as payload and the
  connection continued out of sync — a parser desync, the precondition for smuggling behind
  a proxy. Any masked frame now fails the connection.
* Control frames that nothing listened for were queued for a later listener, so **a flood
  of pings grew memory to gigabytes**.
* The handshake is read from `req.headers` only; TLS identity errors surface as
  `error.code` (`DEPTH_ZERO_SELF_SIGNED_CERT`, `ERR_TLS_CERT_ALTNAME_INVALID`).
* The configured compression window is actually used (every setting ran as `"3KB"`).

---

## HTTP request parsing — `#46456`

* A request target carrying a byte from `0x7f` to `0xff`, or a control character, is
  answered `400` before any handler runs. Bun used to run the handler with `req.url`
  decoded as UTF-8.
* `DEL` (`0x7f`) in a header or trailer value is answered `400` unless the parser is
  lenient.
* `Bun.serve` is unchanged; this is `node:http` / `node:http2`.

## Crypto and structured clone

**`#46387` — reject malformed `CryptoKey` records** · CVSS 5.3

* A hash tag naming no digest (8, 13, 19) returned `true` without writing its result, so the
  key's hash was read from an **uninitialised byte**. Reachable from a child's IPC channel
  with `serialization: "advanced"`.

**`#46410` — follow-up**

* RSA records with no hash, and ChaCha20-Poly1305 keys that are not 32 bytes.

## Availability

**`#46389` — quadratic `Bun.stringWidth`** · CVSS 4.0

* `"日\n" × 200,000`: 6.8 ms in 1.3.14, **2.56 s in 1.4.3**, linear again. Every ASCII run
  starting with a control character scanned the rest of the string for `ESC`.

## Crash hardening

**`#46021` — "Hardening: fix crashes across the runtime, bundler, dev server, shell and CLI"**

* **306 pull requests** folded in (227 whole, 79 cut down) plus ~20 crashes that had no PR:
  segfaults, Rust panics, aborts, failed assertions, sanitizer-reported memory corruption,
  native stack overflows. These now throw a catchable error, print a CLI error and exit 1,
  or work.
* Includes findings this evaluation had tracked as *open*: **#34884** (deep-nested value
  SIGSEGV), **#38009** (MessagePort UAF), **#38636** (`Bun.serve` route UAF after
  `reload()`), **#41574** (UTF-8 decoder on a borrowed buffer), **#42334**, **#42185**,
  **#41710**, **#44124**, **#44195**.

**`#46270` — "Hardening follow-up: fix regressions from #46021 and more crashes"**

* Fixes regressions from #46021 and #44618 that were never released, takes more open
  crash-fix PRs, and includes **#41475** (30,000-combinator selector SIGSEGV in
  `HTMLRewriter`).

## Known regression in this release

**`emSign Root CA - G1` is trusted again.**

#46159 removed four emSign roots on 2026-10-20; #46300 deleted the mechanism the next day
and regenerated, restoring `G1`. NSS 3.131.1 had already dropped the other three, so the
count went 121 → 117 → **118**, with `G1` the only survivor.

| Root | 1.4.3 | after #46159 | 1.4.4 |
|---|---|---|---|
| `emSign Root CA - G1` | present | removed | **present** |
| `emSign ECC Root CA - G3` | present | removed | absent |
| `emSign Root CA - C1` | present | removed | absent |
| `emSign ECC Root CA - C3` | present | removed | absent |

**Not exploitable for the known compromise.** The eight compromised intermediates are issued
by `emSign Root TLS CA - G3`, which is not in NSS's list and not in Bun's bundle at all, and
whose Mozilla-trusted cross-sign (`emSign ECC Root CA - G3`) NSS dropped. Nothing in the
compromised set chains to `G1`. The attack fails three ways over: SPKI blocklist, missing
issuer root, missing cross-sign.

It is a **process regression**: a deliberate removal was undone by two PRs racing, and the
test that documented the exclusion was deleted in the same commit that removed the
mechanism. The cost is the next one — nothing now records that this root was meant to be
distrusted.

Full detail: [`05-next-release.md` §3](05-next-release.md#3-finding-the-emudhra-root-removal-was-undone).
